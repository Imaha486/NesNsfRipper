# NesNsfRipper — NES ROM → NSF 自動抽出ツール（エミュレーション追跡方式）

NES ROM (iNES) をエミュレータ上で自動プレイしながらサウンドドライバを追跡し、
曲/効果音の起動手順を総当たりで列挙して NSF ファイルを生成する Windows 用ツールです。
GUI 版 (`NesNsfRipper.exe`) とコマンドライン版 (`nsfrip_cli.exe`) があります。

## 使い方 (GUI)

1. `NesNsfRipper.exe` を起動し、「開く...」で .nes ファイルを選ぶ（ウインドウへのドラッグ＆ドロップ、
   またはコマンドライン引数でも可）。選ぶと自動で解析が始まります（数秒〜数分）。
2. 解析が終わるとリストに候補が並びます。
   - **種別**: `Music`（長い/ループする）/ `SFX`（短い）
   - **信頼度**: `◎ 使用確認` = ゲーム実行中に実際に呼ばれた引数、`○ 妥当` = テーブル範囲内と推定、
     `△ 範囲外?` = 曲テーブル外のゴミの可能性が高い（デフォルトではチェック無し）、`!` = 追加の疑い
   - **長さ**: 無音になるまでの時間、`∞` は終わらない（`loop` はループ周期検出）
   - **起動手順**: NSF の INIT が再現する動作（`JSR $xxxx (A=..)`, `RAM $xxxx <- 値`, 複数ステップの `SEQ:` など）
3. 行を選んで「▶ 再生」（ダブルクリック/Enter でも可）で試聴。再生は**生成した NSF そのもの**を
   内蔵 NSF プレイヤーで鳴らしているので、NSF プレイヤーで鳴る音と同じです。
4. 出力したい行にチェックを入れて「チェック項目をNSF保存...」。同名の `.m3u` (トラック名付き) も保存できます。
   保存時にトラックごとの検証（ゲーム実行時のレジスタ書き込み列と NSF 再生の書き込み列が一致するか）を
   行い、結果を「NSF検証」列に表示します。

## 使い方 (CLI)

```
nsfrip_cli rom.nes 出力ベース名 [--wav 秒] [--frames N] [--threads N] [--long N] [--nosfx] [--all]
```
解析ログと候補一覧を標準出力に表示し、`出力ベース名.nsf` を書き出します。`--wav 10` で先頭 3 トラックを
10 秒 WAV 化（検証用）。`--all` は範囲外候補も含めて出力します。

## 仕組み

1. **自動プレイ追跡 (2 パス + シード)** — ROM を独自 NES コア (6502 + 主要マッパー + タイミング PPU) で約 40 秒間
   自動操作しながら全 JSR/RTS/割り込みを影スタックで追跡し、APU/拡張音源レジスタへの書き込みを
   どのルーチンの延長内で行っているかを集計します。毎フレーム規則的に呼ばれ書き込みをほぼ網羅する
   ルーチンを **PLAY** とし、PLAY の外側から駆動される「ドライバ RAM への書き込み（メールボックス）」、
   「ドライバ RAM を書くルーチン（INIT 候補）」、「同一フレーム内の連続呼び出し列」「INIT 候補が読む
   ゲーム状態 RAM（ステージ番号など）」を収集します。サウンド初期化直後のスナップショットも保存します。
   2 パス目は 2 回実行し、1 回目で得たドライバ RAM の地図を 2 回目の開始時に流し込みます（起動直後、PLAY が
   その変数を読む前に書かれたリクエスト ― タイトル曲など ― も取りこぼさないため）。ブロック転送/RAM クリアによる
   書き込み、ROM ポインタ対（下位/上位）、ドライバ自身が毎フレーム書き換える作業変数はメールボックスから外します。
2. **総当たり** — スナップショットから `INIT 候補を A/X/Y=0..255 で呼ぶ`, `メールボックスに 0..255 を書く`,
   `RAM 書き込み + JSR`, 観測した呼び出し列とそのシフト変種 などのレシピを数万通り実行し、
   APU 書き込み列のハッシュで重複排除、可聴性チェック（簡易 APU 状態モデル + 合成 RMS）で無音を除外します。
   生き残りは 60 秒走らせて長さ/ループを解析します。可聴性は APU のレングスカウンタ・エンベロープ・
   三角波リニアカウンタまでモデル化しているので、鳴り終わった後にドライバが書き続ける「空振り」の
   レジスタ書き込みを曲の継続と誤認しません。
   スナップショット自体が曲を再生中の場合（ゲームの起動直後から曲が鳴っているなど）は、まず「無音化
   リクエスト」（全候補の中からドライバを黙らせるもの）を探してその直後の状態 S を作り、S から探索し直します。
   S で鳴らせないリクエスト（無音化が一時停止フラグで、曲エンジンが止まる場合など）は元のスナップショット
   から拾い、NSF 側ではトラックごとに使ったスナップショットから RAM 差分を作ります。元のスナップショットで
   見つけた候補のうち、ベース曲に重なっただけで最終的に同じ書き込み列に戻るもの（効果音・ジングル）は
   効果音として分類し、その時点を終端にします。
3. **ゴミ判定** — 曲番号テーブルの境界を推定（引数依存の最初の ROM 読み出し先が、他の候補が
   データとして読む領域やコード領域に入っていれば範囲外）、パラメータ的な引数（ほぼ全値で別出力）の
   抑制（ほぼ全値で同じ構造・同じ書き込み数の出力しか出ない変数はテンポ/ピッチ等のパラメータとみなし降格）、
   実際に観測した値は `◎` にします。PLAY 候補が複数ある場合はそれぞれ探索し、観測済みリクエスト数と
   妥当な曲数によるスコアで最良の試行を採用します。
4. **NSF 生成** — PLAY が使用する 4KB ページだけを NSF バンクに詰め、空きスロットに「スタブ」バンクを置きます。
   INIT スタブは (a) ドライバが読む RAM をスナップショットから復元、(b) 各トラックの起動動作を
   **ゲーム実行時に記録した RAM 差分 + サウンドレジスタ書き込み列として再生**（ゲームのコードは NSF 内で
   実行しないので安全）、PLAY スタブは毎回バンク構成を固定してドライバの更新ルーチンを呼びます。
   ドライバ自身がマッパーレジスタを書く場合は該当命令を `JSR シム` に差し替え、シムが NSF の
   `$5FF8-$5FFF` バンク切替に翻訳します（MMC1/MMC3/UxROM/AxROM/GxROM/Bandai/N163/VRC1/VRC2/VRC7/
   Taito/Sunsoft-3/FME-7 対応）。`$2002` 読み出しは RAM 上の擬似ステータスに差し替えます。
   8 スロット全部をドライバが使う場合は RAM 上のトランポリンで PLAY を呼びます。
5. **検証** — 生成した NSF を内蔵 NSF プレイヤーで再生し、ハーネス実行時の書き込み列と比較します。
   拡張音源 (N163 / Sunsoft 5B / VRC7) もヘッダのフラグを立て、試聴用に簡易合成します。

## ビルド

- Visual Studio: `vs/NesNsfRipper.sln` (x64, C++17, 外部依存なし)
- MinGW: `x86_64-w64-mingw32-g++ -std=c++17 -O2 -municode -mwindows -static src/{nes,synth,tracer,brute,nsfgen,gui}.cpp res/app_res.o -lcomctl32 -lwinmm -lcomdlg32 -lgdi32 -lshell32`
- Linux (CLI のみ): `g++ -std=c++17 -O2 src/{nes,synth,tracer,brute,nsfgen,cli}.cpp -lpthread -o nsfrip_cli`

## 制限事項

- 自動プレイで到達しない状態（特定ステージの曲など）は「使用確認」になりませんが、
  曲番号の総当たりで大抵は拾えます。ステージ番号などゲーム状態に依存する起動は「RAM $xxxx <- 値; JSR」として
  部分的にしか列挙できません。
- 曲テーブルの境界推定はヒューリスティックです。`△` の候補も試聴して判断してください。
- 曲中に DPCM 以外の目的でマッパー IRQ を使うドライバ、`STA (zp),Y` などでマッパーを書くドライバは
  曲中バンク切替を再現できません（検証が NG になります）。
- 拡張音源の合成は試聴用の簡易実装です（VRC7 は近似）。
- NSF の INIT/PLAY は `$5FF8` バンク切替に対応したプレイヤー（NSFPlay, foobar2000+GEP, Winamp NEZplug 等）を想定しています。

## 更新履歴

- v1.4: DB 系ツールでカバーされない同人・海外タイトル向けに探索を強化。
  (1) スナップショットを「起動直後 (A)」「最初の音から 90 フレーム後で音が鳴っている瞬間 (B)」「後半で音が鳴っている瞬間 (C)」
  の 3 点に増やし、実際にゲーム中で観測されたリクエストで曲が出るまで順に探索（Mojon Twins 系エンジンのように
  曲 API がドライバ初期化後にしか効かないタイトル：Cheril the Goddess 0→5 曲、Lala the Magical 0→6 曲、Super Uwol 4→10 曲）。
  (2) ゲームが一度も呼ばなかったルーチンも拾う「静的候補」：ドライバコード近傍への JSR 先を ROM から走査し INIT 候補に追加
  （自動プレイがタイトル画面から進まない RHDE など、FamiTone の music_play のような未使用 API を発見）。
  (3) PLAY がシャドウレジスタの転送だけで、曲の計算を別のフレーム毎ルーチンが行う「インラインエンジン」構成
  （Owlia など）を検出：PLAY 単体の出力が毎フレーム同一なら、ドライバ RAM の大半を書くフレーム毎ルーチンを PLAY の前段に組み込む。
  (4) PLAY のレジスタがモード指定になっているドライバ向けに、A=X=Y=0 で曲が出ない場合は観測したレジスタで再探索。
  (5) 無音化スナップショット S の検証プローブを複数化（PLAY 再入のような「何もしないリクエスト」で全停止候補を却下していた）、
  元スナップショットから残す候補を「S から鳴らず、ベース曲の位相ずれでもなく、ゲーム中に観測されたもの」に限定。
  (6) ノート判定でピリオド 0 の書き込みを除外（アイドル中のドライバが毎フレーム 0 を書くタイトルで自動プレイ評価が狂っていた）。
  (7) NES コア: vblank の NMI を「実行中の命令 2 つ分」遅らせ、`BIT $2002` でフラグをポーリングするメインループが NMI ハンドラの
  `$2002` 読み出しに先を越されて永久に待つ問題を修正（Assimilate などが起動するようになった）。1 スキャンラインごとに約 1 サイクル
  長くなっていたフレーム長も修正（サイクル同期ループを使う同人作が動くようになった）。
  (8) ゴミ対策: 160 値以上で「鳴る」変数が 3 つ以上あるとき（チャンネルレジスタを直接書くメールボックス）はレジスタ的変数として降格、
  試行スコアで同一リクエスト形の寄与を 12 件までに制限、PLAY 代替候補はサウンド書き込みの 25% 以上を担うものに限定（効果音サブエンジンを
  PLAY にしてゲームロジックを「リクエスト」として拾うのを防止）。入力パターンの切替は明確に改善した場合のみ。
  同人 68 本: NSF 生成 43→49 本、全トラック一致 34→39 本（RESULTS_homebrew.md）。手持ち 71 本: トラック一致 3655/3754→3965/4010（RESULTS.md）。
- v1.3: 「ファミコン音楽V2」（手作業 DB 方式の NSF 化ツール）の収録データを答え合わせに使い、取りこぼしの原因を潰した。
  (1) リクエスト API が INIT 候補の上位 20 に入らない（DQ4 など）→ APU レジスタを直接触るルーチンを優先し、
  1 回あたりの書き込みが多い一括処理ルーチンや、ドライバ以外の RAM も大量に書くルーチンを降格。
  (2) PLAY が汎用テンポラリ（$00-$07 など）を読むため、ゲーム中のほぼ全ルーチンが「ドライバを書く」扱いに
  なっていた（レインボーアイランド）→ 多数の箇所から多数回書かれる共有バイトをドライバ変数から除外。
  (3) 32K/16K バンクごとにドライバと曲データの複製を持つ構成（ドラえもん等）→ ドライバが切替バンク内に
  あり自分でバンク切替をしない場合、全バンクで同じリクエスト形を再探索する「バンクスイープ」を追加
  （バンクごとにアイドル時の挙動が本物のドライバと一致することを確認してから採用）。トラックごとに PLAY の
  バンク構成を持てるよう NSF 生成を拡張（候補欄に `@bank ...` と表示）。
  (4) 観測した呼び出し列のシフト変種を ±255 に拡大、同じルーチンをレジスタをインクリメントしながら呼ぶ
  「バースト」形のリクエストに対応。VS プロジェクトのマニフェスト二重定義（CVT1100）を修正。
  RESULTS_db.md に DB との比較表を追加。
